## 3. 画風の基準

全アセットで次を共通にする。最初の1枚（4.1 の画風の見本）で確定させ、以後はその画像を参照として毎回添付する。

> 暗いダークファンタジーのスーパーファミコン風ドット絵。灰と煤が舞う、くすんだ色調。人物はデフォルメ寄りの等身とし、輪郭はドットの縁取りではっきりさせ、陰影は少ない段数で形を見せる。光源は炎・篝火・曇天の白い光など、場面の光に限る。

- **画風の見本が伝えるのは画風だけ**：見本（`ASSET_HERO_STANDING.png`）を添付して生成すると、依頼文に書かなかった部分（顔、髪形、服装の形と色、持ち物、ポーズ）が見本に似る。人物どうしが似ると [S-LOOK-PRINCIPLE] の見分けが崩れるため、見本を添付するときは 4.2 の「参照の一文」で、参考にする範囲を限る。

- **ドットの格子**：画面は論理解像度 1280×720 の2画素を1ドットとする格子（640×360 ドット）で揃える。生成した画のドットの細かさは画ごとに異なり、そのまま縮めると、画面に占める大きさの小さい立ち絵のドットが背景より細かくなる。取り込み（`pnpm art`）で、立ち絵は 64×96 ドット、背景は 640×360 ドットに縮め、画面では最近傍で拡大して描く（ドットを滲ませない）。依頼文にも狙いのドット数を書き、縮めたときに潰れる細部を減らす。
- **モノクロで見分けられること**：人物は、色を抜いても輪郭・髪形・持ち物で見分けられるように描く（[S-LOOK-PRINCIPLE]）。
- **季節**：作中は七〜八の月である。息を白く描かない。
- **画面の向き**：味方（セイン・従者）は右を向く。敵と仮身は左を向く。

## 4. 生成の手順

### 4.1 画風の見本を作る

1. ChatGPT で新しい会話を始める。
2. 「5.2 セイン（基準）」の依頼文を送る。
3. できた画を確認する。画風を変えたい場合は、その場で直しを頼み、満足するまで繰り返す。
4. 確定した画を、リポジトリの中の `art-src\` に `ASSET_HERO_STANDING.png` として保存する。
5. 確定した画を Claude Code に見せる（パスを伝える）。画面に組み込んだ見え方を確かめてから、残りへ進む。

### 4.2 残りを生成する

- **1体につき1つの会話**：人物・仮身・背景は、1枚ごとに新しい会話で生成する。同じ会話で続けると、前の画に引き寄せられて人物どうしが似る。ただし、元の画と似せるのが目的の差分（2 の外套の差分、18 の開幕、30・31 の広場の差分）は、元の画を生成した会話で続けて生成する。15 の結晶の小腕は、11 の画も添付する。
- **参照の一文**（人物・仮身）：新しい会話の最初に `ASSET_HERO_STANDING.png` を添付し、依頼文の前に次の一文を書く。「この画像と同じ画風で」とだけ書かない。背景は下記の「背景の参照」による。

  > 添付画像からは、ドットの細かさ、輪郭線の扱い、陰影の段数、色の彩度、等身の比率だけを参考にしてください。添付画像の人物の顔・髪形・服装・色・持ち物・ポーズは参考にせず、以下の説明だけに従ってください。

- **背景の参照**：背景は、人物の画ではなく、確定済みの背景の画を参照として添付する。立ち絵は被写体に対してドットが粗く、風景の画のドットの細かさや空気感の見本に向かないうえ、人物の画を添付すると、背景に人物が描き込まれたり、外套の赤など人物の色が画面全体に移ったりしやすい。
  - 添付する画は `ASSET_BG_1_01.png`（1-01 の戦闘の画。確定済み）とする。16 のタイトルと 17 の 1-01 自身を除く背景を新しい会話で生成するときに用いる。上記の「1体につき1つの会話」が元の画の会話で続けて生成するとする差分（18 の開幕、30・31 の広場の差分）は、元の画が会話にあるため改めて添付しない。
  - 新しい会話の最初に `ASSET_BG_1_01.png` を添付し、依頼文の前に次の一文（背景の参照の一文）を書く。人物の「参照の一文」は用いない。

    > 添付画像からは、ドットの細かさ、輪郭線の扱い、陰影の段数、色の彩度、光の扱いだけを参考にしてください。添付画像の場所・建物・地形・構図・色の取り合わせは参考にせず、以下の説明だけに従ってください。人物は描かないでください。

  - `ASSET_BG_1_01.png` を作り直した場合は、それより後に生成した背景との画風の揃いを確かめる。
- 1枚ごとに、本書の依頼文を送る。依頼文の「（5.1 の共通の一文）」「（6.1）」などの箇所は、該当する節の引用の一文に置き換えて送る。
- 気に入らない場合は、直してほしい点を具体的に伝えて作り直す。

### 4.3 保存

- 保存先はリポジトリの中の `art-src\` とする。このフォルダは Git の対象から外してあり（`.gitignore`）、元の画像はコミットされない。
- ファイル名は本書の `asset_id` に `.png` を付けたものとする（例：`ASSET_BG_1_01.png`）。
- 作り直した場合は上書きする。
- 生成した日付と会話（共有リンクを作れる場合はそのリンク）を、`art-src\log.txt` に1行ずつ書き残す。AIの使用の記録に用いる。

## 5. 立ち絵

### 5.1 共通の決まり

- **寸法**：縦長（1024×1536）で生成する。Claude Code が、全身が縦96ドット・横64ドットの枠に収まるよう縮めて書き出す（3「ドットの格子」）。
- **背景**：透明。透明にできない場合は、無地の明るい灰色とする（Claude Code が切り抜く）。
- **構図**：全身を頭から足先まで入れる。上下に少し余白を残す。床・地面・影を描かない。
- **用途**：盤面の1マス（およそ 320×208 の枠の中、高さ 192px。足元はユニットプレートの中央に掛かる）とインターミッションの壇に置く。全身が縦96ドットになるため、顔の細部は数ドットに潰れる。目鼻より、髪形・輪郭・持ち物・服の色の塊で人物が分かるように描かせる。
- **目**：目を1つずつ描き込まず、眉の線や前髪の影で、目元を1〜2ドットの暗い帯として表す。全身が縦96ドットでは目は1〜2ドットに潰れ、描き込んだ目は縮めると明暗の点の乱れになるためである。目を描かずに素肌のままにすると顔がのっぺりとして不気味になるため、帯は残す。目の色・目つき・視線は依頼文に書かず、表情は口元・眉・首の傾きと姿勢で表す。
  - 本項を定める前に生成した立ち絵は目を描き込んでいる。揃えるには作り直す。
- **ポーズ**：依頼文ごとに、腕と手の位置を含めて書く。書かなかった部分は画風の見本のポーズに似るためである（3）。外見設定に定めの無いポーズは、人物の役割と性格を示す控えめなものとする。

依頼文の末尾の「共通の指定」には、次の一文を貼り付ける。

> 共通の指定：縦長の画像。全身を頭から足先まで入れ、上下に少し余白を残す。背景は透明。床・地面・影・文字・数字・記号は描かない。暗いダークファンタジーのスーパーファミコン風ドット絵、くすんだ色調。全身が縦およそ100ドットのスプライトとして描き、1ドットを大きく、ドットの粒が見えるように描く。目は描かない。現代的なアニメイラスト、滑らかなデジタルペイント、3Dレンダリングにはしない。

## 6. 背景

### 6.1 共通の決まり

- **寸法**：横長（1536×1024）で生成する。Claude Code が 16:9 に切り出し、640×360 ドットに縮めて書き出す（3「ドットの格子」）。
- **構図の決まり**（[S-BG-PRINCIPLE]）：
  - 地面は、画面の中ほどからやや下に、水平な帯として置く。消失点は画面の中央の高さに合わせる。
  - 地面の帯の上に、人物や大きな物を置かない（戦闘の画では、ここに立ち絵が4体並ぶ）。
  - 来た方角が左、進む先が右である。
  - 人物を描かない（指示がある場合を除く）。
- **用途**：戦闘の画は、盤面の帯（高さ 208px）の背後に、地面の帯が立ち絵の足元に来るよう置く。上下は大きく隠れるので、見せたい物は画面の中段に置く。演出の画（開幕・撃破後など）は、脚本の文章の背後に暗くして全面に敷く。

依頼文の末尾の「共通の指定」には、次の一文を貼り付ける。

> 共通の指定：横長の画像。ゲームの背景で、人物は描かない。文字・数字・看板の文字は描かない。暗いダークファンタジーのスーパーファミコン風ドット絵、くすんだ色調、灰が舞う空気感。画面全体が横およそ640ドットの粗さで描く。

戦闘の画の「戦闘の画の指定」には、さらに次の一文を貼り付ける。

> 戦闘の画の指定：地面は画面の中ほどからやや下に、左右へ水平に広がる平らな帯として描き、その上には何も置かない（あとで人物を4人横一列に並べる）。消失点は画面の中央の高さ。

## 7. 受け渡しの後

Claude Code が次を行う。

1. `art-src\` の画像を切り抜き・縮小し（立ち絵は PNG、背景は JPEG）、`src/ui/public/art/` に置く。
2. 表示アセットマスタ（`tools/genmaster/authoring/assets.js`）に本書の `asset_id` のレコードを加え、`path` を実体に向ける。
3. 審査範囲の脚本の各行に `background` を与える。
4. 画面（タイトル、脚本、バトル、インターミッション、補充）に組み込み、配布版で見え方を確かめる。
5. `docs/ai-usage.md` の「表示アセット・音声」の表に、`asset_id` ごとの行を書く。

## 8. 未決の事項

- **仮身の造形とクリーチャーの記録**：合本の [M-DATA-CREATUREID] はシーンごとに仮身の記録を分ける（2-01 は `CREATURE_STITCHED` など）が、実装は強さの帯ごとの共通の記録（`CREATURE_THRALL_AR*`）を作っている。2-04 の `AR9` は 3-01 と共有している。審査範囲では帯ごとに画を当てれば正しく見せられるが、3-01 の仮身が 2-04 の画で出る。合本どおりに記録を分けると、同じ帯の召喚の行動の扱い（継承での統合）にも影響するため、別に判断する。
- **音声**：生成AIで用意する。ツールは画像の後で決める。
