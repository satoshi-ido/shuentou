# 初見の試験の手引きと記録用紙

[I-PLAN-SUBMISSION]【初見の試験】を行うための手順と用紙である。合本には含めない。結果は試験の後に [V-TEST-NONFUNC] へ転記する。

## 1. 目的と合否

二次審査では、審査員が ZIP を展開して初見で遊ぶ。同じ条件で、本作を遊んだことのない人に審査範囲（アクト1・2、1-01〜2-04）を遊んでもらい、次を確かめる。

| 確かめること | 合否の基準（[I-PLAN-SUBMISSION]【M9 の受け入れ線】5・【審査範囲】） |
| :---- | :---- |
| 先へ進めなくなる箇所 | 助言を要した箇所をすべて解消するか、解消しない理由を記録する |
| 審査範囲の終わりまでの所要時間 | およそ30分で到達できるか（【審査範囲】1）。超える場合は、入口を設けるか序盤の構成を改めるかを判断する |
| 回帰の役割の理解 | 参加者の過半が、本人の言葉で説明できる |
| 未来予測タイムラインの役割の理解 | 説明できたかを記録する（合否には含めない） |
| 面白い箇所、退屈・分かりにくい箇所 | 記録する |

参加者は3名以上とする。

## 2. 準備

### 機体

- [ ] Windows 11 の機体を用意する。参加者の私物でもよい。
- [ ] 機体の情報を記録用紙に書く。CPU、メモリ、GPU、画面の解像度を `設定 > システム > バージョン情報` で確認する。
- [ ] 描画の滑らかさも、この機体で見る（[I-PLAN-SUBMISSION]【基準機】「仮想マシンで再現しないもの」）。

### 提出版の候補

- [ ] 提出版の候補の ZIP を用意し、コミットの ID を記録用紙に書く。
- [ ] 前の参加者のデータを消す。`%APPDATA%\Shuentou` を削除する（エクスプローラーのアドレス欄に `%APPDATA%` と入力して開く）。
- [ ] ZIP は展開しないまま、デスクトップに置く。展開から起動までも審査員と同じ手順で行ってもらう。

### 記録

- [ ] 時計を用意する。経過時間は「ZIP に触れた時点」を 0:00 とする。
- [ ] 画面を録画する場合は、参加者に同意を得る。Windows の録画は `Win + Alt + R`（Xbox Game Bar）で始めて止める。音声も録る場合は、それも伝えて同意を得る。
- [ ] 本書の「4. 記録用紙」を参加者ごとに1部用意する。

## 3. 進め方

### 3.1 始める前に参加者へ伝えること

次の文を読み上げる。これ以外の説明（遊び方、物語、システム）はしない。

> これから、開発中のゲームを初めて遊んでもらいます。遊び方の説明はしません。ゲームの中の案内だけを頼りに進めてください。
>
> デスクトップにある ZIP を展開して、ゲームを起動するところから始めてください。展開の仕方は、ZIP の中の説明書きにも書いてあります。
>
> 目標は、ゲームの中で「アクト2」と呼ばれる区切りの最後の戦いを終えるところまでです。そこまで来たら、こちらからお知らせします。
>
> 遊んでいるあいだ、思ったことや迷ったことを、できれば口に出してください。黙って遊んでも構いません。
>
> 困っても、私からは基本的に口を出しません。どうしても進めなくなったら、そう言ってください。そのときは手助けします。手助けが必要になった箇所こそ、私が直したい箇所です。遊び方が下手だということではありません。
>
> 時間はおよそ30分を見込んでいます。途中でやめたくなったら、いつでもやめて構いません。

### 3.2 観察の決まり

- 操作に口を出さない。画面を指さしたり、うなずいたりもしない。
- 参加者に質問されたら、「ゲームの中で探してみてください」と返す。
- **助言をする条件**：次のどれかに当たるときに限る。
  - 参加者が「進めない」と言った。
  - 同じ画面のまま3分以上、先へ進む操作がない。
  - 同じ戦いに5回続けて負けた。
- 助言は、いちばん小さいものから順に1段ずつ出す。
  1. 「画面のどこかに手がかりがあります」（場所を示さない）
  2. 見るべき場所だけを示す（例：「画面の上の帯を見てください」）
  3. 操作を具体的に教える
- 助言を出したら、その時刻・箇所・段階・内容を記録用紙に書く。
- 参加者が自分で解決したら、助言は出さず、詰まった時間だけを書く。

### 3.3 終わり方

- 2-04「シャルム陥落」の戦いに勝ち、撃破後の文章を読み終えて、次のインターミッション（継承・編成の画面）が出たところで終える。その時刻を記録する。
- 45分を過ぎたら、その時点で終える。どこまで進んだか（シーン）を記録する。
- 終えたら、すぐに「3.4 聞き取り」へ進む。

### 3.4 聞き取り

参加者がゲームの画面を見ないまま答えるようにする。答えを誘導しない。参加者の言葉をそのまま書き取る。

1. 遊んでみて、どうでしたか。（自由に）
2. 面白いと感じたのは、どこですか。
3. 退屈だった、または分かりにくかったのは、どこですか。
4. 戦いの画面の上のほうにあった、横に長い帯（タイムライン）は、何を表していたと思いますか。それを見て、何かを決めましたか。
5. 負けたときや、やり直したいとき、どうしましたか。そのやり直しは、どんなものだと思いましたか。
6. 物語の中で、主人公が「やり直す」ことには、どんな意味があると思いましたか。
7. この続きを遊びたいと思いますか。それはなぜですか。
8. ほかに気づいたことはありますか。（動きの重さ、文字の読みやすさなどを含む）

質問 4・5・6 は、参加者が「分からない」と答えてもよい。その答えもそのまま書く。

### 3.5 理解の判定

聞き取りの答えを、次の基準で判定する。判定は試験の後に行い、迷ったら「部分」とする。

**回帰の役割**（質問 5・6）

| 判定 | 基準 |
| :---- | :---- |
| 説明できた | 次の (a) と、(b)・(c) のどちらかを、本人の言葉で述べた |
| 部分 | (a)・(b)・(c) のどれか1つだけを述べた |
| 説明できない | どれも述べなかった、または「便利なやり直し機能」以上の意味を述べなかった |

- (a) 戻ってやり直せる。戻る先は戦いの始まりか、過去のインターミッションである。
- (b) 同じ手を打てば同じ結果になる。運に左右されず、やり直しで手を正せる。
- (c) やり直すと、前に知ったことが場面に現れる（2-04 の前に戻ると、開幕の場面が前と変わることなど）。または、やり直しが作中の出来事として数えられる（燈の数字が増える）。

[S-CONCEPT-REGRESSION] は「初見のプレイヤーはこれを知らず、アンドゥやロールバックを便利な巻き戻し機能として使う」とする。審査範囲での理解の目標は (a) と (b) である。(c) まで述べた参加者は、記録の備考に書く。

**未来予測タイムラインの役割**（質問 4）

| 判定 | 基準 |
| :---- | :---- |
| 説明できた | 敵や自分の技が、いつ発動し、いつ終わるかが分かるものだと述べた。または、それを見て技を出す時機を決めたと述べた |
| 部分 | 「時間の流れ」「順番」程度に述べた |
| 説明できない | 述べなかった |

## 5. 試験の後

全員の試験を終えたら、次をまとめて [V-TEST-NONFUNC] へ記録する（合本の変更は人がコミットする）。

- 参加者ごとの所要時間と、到達したシーン
- 助言を要した箇所の一覧（箇所・時刻・段階・内容）と、それぞれの対処（解消した／解消しない理由）
- 回帰とタイムラインの理解の判定と、過半の成否
- 面白い箇所と、退屈・分かりにくい箇所の要約
- 不具合と、試験に用いた機体での動きの滑らかさ

ガルドの残響を見ないまま進んだ参加者がいた場合は、その人数と捧げた時点をまとめ、残響を見逃す道に手当てをするかを判断する。

所要時間がおよそ30分を大きく超える場合や、同じ箇所で複数の参加者が詰まった場合は、[I-PLAN-SUBMISSION]【審査範囲】の判断（審査範囲への入口を設けるか、序盤の構成を改めるか）に進む。
